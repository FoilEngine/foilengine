# 09 — AI (`@foilengine/mind`) and simulations (`@foilengine/sim`)

## Interface

```ts
interface Policy {
  id: string;
  decide(view: PlayerView, legal: ActionTemplate[], budget: Budget, rng: Rng): Promise<Decision>;
}
interface Decision { action: Action; explanation?: Explanation }
interface Explanation { evaluation: number; rollouts?: number; alternatives?: { action: Action; evaluation: number }[] }
```

- A policy only sees **the player's view** (`viewFor`). It does not cheat.
- It receives a **budget** (time or number of simulations) and its own seeded RNG: an AI decision is reproducible.
- It returns an **explanation**: the evaluation of its move and of the alternatives. That is what the client displays under the card played by the AI ("eval +0.42 · 1,200 rollouts").

## Policies, in development order

1. **`random`**: a random legal action. Used for fuzzing and tests.
2. **`greedy`**: a simple heuristic (play the best possible unit, attack when it is favorable).
3. **`mcts`**: Monte Carlo Tree Search with **determinization**: sample the hidden cards (opponent's hand and deck) consistently with what is known, run simulations, and aggregate over several samples (ISMCTS variant).
4. **`mcts+eval`**: MCTS whose simulations stop early and use an evaluation function (points, battlefield control, card advantage, resources).
5. Later: an evaluation learned through self-play. Training data comes from the log; the weights will go into a separate `models` repo.

## Where the AI runs

- **In the client**, in a Web Worker, to play against the AI offline or without server load.
- **On the server or the workers**, for analyzed games, simulations and puzzles.

## The weak spot

For a given deck, `sim` measures the impact of each card: games are replayed with the card removed or replaced, and the win rates are compared. The cards with the most negative impact are the weak spots, with a confidence interval. Same principle for moves during a game: the evaluation gap between the move played and the best move found.

## Mass simulations (`sim`)

- A **job**: two decks (or more), a mode, a number of games, policies, a seed.
- Run by workers through the job queue; results in the database.
- Output: win rate with a confidence interval (Wilson), first or second player split, game length, the cards most involved in wins and losses.
- Games with unimplemented cards are **excluded** or flagged, never counted silently.
- A simulation is reproducible: same job, same seed, same results.

## Measuring the AI

A nightly tournament between policies (`random`, `greedy`, `mcts` at different budgets) on a panel of decks. A significant drop in a policy's win rate compared with the day before triggers a non-regression alert.
