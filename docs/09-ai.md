# 09 — IA (`@foilengine/mind`) et simulations (`@foilengine/sim`)

## Interface

```ts
interface Policy {
  id: string;
  decide(view: PlayerView, legal: ActionTemplate[], budget: Budget, rng: Rng): Promise<Decision>;
}
interface Decision { action: Action; explanation?: Explanation }
interface Explanation { evaluation: number; rollouts?: number; alternatives?: { action: Action; evaluation: number }[] }
```

- Une politique ne voit **que la vue du joueur** (`viewFor`). Elle ne triche pas.
- Elle reçoit un **budget** (temps ou nombre de simulations) et son propre RNG à graine : une décision de l'IA est reproductible.
- Elle renvoie une **explication** : l'évaluation de son coup et des alternatives. C'est ce que le client affiche sous la carte jouée par l'IA (« eval +0.42 · 1 200 rollouts »).

## Politiques, dans l'ordre de développement

1. **`random`** : une action légale au hasard. Sert au fuzzing et aux tests.
2. **`greedy`** : une heuristique simple (jouer la meilleure unité possible, attaquer quand c'est favorable).
3. **`mcts`** : Monte Carlo Tree Search avec **déterminisation** : on échantillonne les cartes cachées (main et deck adverses) de façon cohérente avec ce qui est connu, on lance des simulations, et on agrège sur plusieurs échantillons (variante ISMCTS).
4. **`mcts+eval`** : MCTS dont les simulations s'arrêtent tôt et utilisent une fonction d'évaluation (points, contrôle des battlefields, avantage de cartes, ressources).
5. Plus tard : une évaluation apprise en self-play. Les données d'entraînement viennent du journal ; les poids iront dans un repo `models` séparé.

## Où tourne l'IA

- **Dans le client**, dans un Web Worker, pour jouer contre l'IA hors ligne ou sans charge serveur.
- **Sur le serveur ou les workers**, pour les parties analysées, les simulations et les puzzles.

## Le point faible

Pour un deck donné, `sim` mesure l'impact de chaque carte : on rejoue des parties en retirant ou en remplaçant la carte, et on compare les taux de victoire. Les cartes dont l'impact est le plus négatif sont les points faibles, avec un intervalle de confiance. Même principe pour les coups en cours de partie : l'écart d'évaluation entre le coup joué et le meilleur coup trouvé.

## Simulations en masse (`sim`)

- Un **job** : deux decks (ou plus), un mode, un nombre de parties, des politiques, une graine.
- Exécuté par des workers via la file de jobs ; résultats en base.
- Sortie : taux de victoire avec intervalle de confiance (Wilson), répartition premier ou second joueur, durée des parties, cartes les plus impliquées dans les victoires et les défaites.
- Les parties avec des cartes non implémentées sont **exclues** ou signalées, jamais comptées sans le dire.
- Une simulation est reproductible : même job, même graine, mêmes résultats.

## Mesurer l'IA

Un tournoi nocturne entre politiques (`random`, `greedy`, `mcts` à différents budgets) sur un panel de decks. Une baisse significative du taux de victoire d'une politique par rapport à la veille déclenche une alerte de non-régression.
